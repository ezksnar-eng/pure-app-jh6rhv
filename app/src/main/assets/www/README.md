# تطبيق مانجا بيور — نسخة 7

## سبب المشكلة اللي شفتها بالصور (وين انحلت)
كانت 3 أخطاء متراكبة سببت ظهور بيانات وهمية بدل بياناتك الحقيقية:

1. **اسم المجموعة غلط**: كودي كان يقرأ من مجموعة اسمها "مانغا" (عربي)، بينما قاعدة بياناتك الحقيقية اسم المجموعة فيها **"manga"** (لاتيني) بالضبط متل ما شفت بلوحة Firebase تبعك. صلحتها.
2. **بنية الفصول غلط**: كودي كان يدور على مجموعة فصول منفصلة بحقل workId، بينما فصولك الحقيقية مخزّنة كمجموعة فرعية تحت كل عمل (`manga/{id}/chapters`) — نفس اللي شفته بلوحتك بالضبط. صلحتها.
3. **البيانات الوهمية**: كان فيه كود يحط 3 أعمال تجريبية ("ظل التاج المفقود"...) تلقائياً بس إذا فشل الاتصال بقاعدة البيانات (كنوع من التخزين المحلي الاحتياطي). هذا هو بالضبط اللي شفته بصورتك — يعني الاتصال بـFirebase كان يفشل بصمت والتطبيق يرجع للتخزين المحلي الفاضي ويعبّيه ببيانات وهمية. **حذفت دالة البيانات الوهمية نهائياً** — إذا صار فشل اتصال الحين، بتشوف رسالة صريحة "تعذّر الاتصال بقاعدة البيانات" بدل بيانات وهمية.

## إذا رجعت المكتبة فاضية بعد
افتح أدوات المطور بالمتصفح (F12 أو Inspect) وشوف تبويب Console — لو صار خطأ اتصال براح يطبع هناك بالضبط شنو السبب (بفضل الإضافة الجديدة `Store.error`). ابعثلي نص الخطأ وأقدر أساعدك بالضبط.

## تعديلات إضافية طلبتها
- `getWorks()` تجيب من `getDocs` حقيقي (مو وهمي)، وترجع النتائج **مرتبة حسب createdAt تنازلياً** تلقائياً.
- حقل الغلاف يقبل **cover أو coverUrl** — أيهما موجود يُستخدم.
- باقي الحقول الناقصة (type, status, latestChapter...) توضع لها قيم افتراضية معقولة بدل ما تطلع فاضية أو تكسر العرض.
